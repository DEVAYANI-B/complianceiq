ComplianceIQ Project Analysis
===========================

Overview
--------
This project is a lightweight compliance-focused RAG application built with a FastAPI backend and a Streamlit frontend. It allows users to upload regulatory documents or company policies, extract text from those documents, split the text into chunks, generate embeddings, store the chunks in a vector database, and then ask compliance-related questions or perform policy-vs-regulation gap analysis using Google Gemini.

What the project does
---------------------
1. Uploads documents (PDF, TXT, PNG, JPG)
2. Extracts text from them
3. Chunks the text for retrieval
4. Generates embeddings
5. Stores embeddings and chunks in ChromaDB
6. Answers user questions with Gemini using retrieved context
7. Compares policy vs regulation for compliance gaps

Project structure
-----------------
- README.md
  Basic setup instructions for running the app.

- requirements.txt
  Lists the Python dependencies for the codebase.

- app/main.py
  FastAPI application entry point.

- app/routes/upload.py
  Handles document upload and indexing.

- app/routes/query.py
  Handles question answering and gap analysis requests.

- app/models/schemas.py
  Pydantic models for API request/response payloads.

- app/services/ingestion.py
  Routes file extraction logic by file type.

- app/services/ocr.py
  Uses Tesseract and Pillow for image OCR.

- app/services/chunker.py
  Splits text into overlapping chunks using LangChain.

- app/services/embeddings.py
  Generates embeddings using Google generative AI embeddings.

- app/services/vectorstore.py
  Uses ChromaDB for persistent vector storage and retrieval.

- app/services/rag.py
  Implements the retrieval-augmented generation pipeline and gap analysis.

- frontend/streamlit_app.py
  Streamlit UI for uploads, question answering, and gap analysis.

End-to-end flow
---------------
1. The user uploads a file in the Streamlit UI.
2. The backend reads the file bytes.
3. The file is converted into text, either from PDF text extraction, OCR, or plain text decoding.
4. The extracted text is split into chunks.
5. Each chunk is embedded with Google’s embedding model.
6. The chunks and embeddings are saved to ChromaDB.
7. When the user asks a compliance question, the question is embedded and compared against stored chunks.
8. The most relevant chunks are retrieved and inserted into a Gemini prompt.
9. Gemini returns an answer and the related source documents/chunks.
10. The gap analysis feature compares regulation and policy chunks and asks Gemini to explain risks and gaps.

Strengths
---------
- Clear separation between API, services, and UI
- Uses modern vector search and LLM-based RAG flow
- Supports both document upload and compliance reasoning
- Persistent vector store through ChromaDB

Weaknesses / limitations
------------------------
- Dependency versions in requirements.txt are not fully compatible in the current environment
- The app depends on external API keys and services
- OCR depends on Tesseract being installed and available
- No authentication, user roles, test suite, or production hardening are included
- No built-in document update/delete/reindex flow

Verification notes
-----------------
The backend root endpoint was verified to respond with:
{"message": "ComplianceIQ API is running"}

The current dependency install also showed a package conflict in the environment, which means the application is not yet fully stable from a clean install.

Conclusion
----------
This is a solid prototype for a compliance-oriented RAG assistant. It demonstrates the core architecture well, but it still needs dependency cleanup and production hardening before it can be considered fully reliable for real deployment.
